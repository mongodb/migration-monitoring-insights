# Release notes

When making a major change, maintain `RELEASE_NOTES.md` at the repo root.

- Record every major change in the release notes file. Do not skip changes that look significant.
- Keep entries short and human-readable: what changed, why it matters to users or operators, and any action required (config changes, migrations, breaking behavior).
- Add new entries to the unreleased section at the top of the file. Do not rewrite or delete past release entries.
- If `RELEASE_NOTES.md` does not exist, create it before recording the first change.
- Keep the file's changes in the same change set as the code they describe.
